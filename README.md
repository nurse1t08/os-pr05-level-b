# Практическая работа № 5 — уровень B

**Тема:** FCFS, SJF, SRTF, Priority, RR и старение процессов.

## Запуск

```bash
bash run.sh
```

Для PNG-графика дополнительно установите `matplotlib`: `python3 -m pip install -r requirements.txt` (в Ubuntu рекомендуется виртуальное окружение `python3 -m venv .venv && source .venv/bin/activate`). Даже без matplotlib таблицы создадутся.

```bash
python3 sched.py --algo rr --quantum 3 set1.txt
python3 sched.py --algo srtf set2.txt
python3 sched.py --algo priority --aging 2 set3.txt
python3 experiment.py
```

В `sched.py` общая функция `simulate(processes, algorithm, **params)` возвращает интервалы `(start,end,pid)`. Считаются: ожидание = завершение−прибытие−burst; оборот = завершение−прибытие; отклик = первый старт−прибытие; загрузка = busy/makespan. Переключение учитывается между интервалами **разных** процессов, без простоя.

## Эталон set1

| Алгоритм | Среднее ожидание | Средний оборот |
|---|---:|---:|
| FCFS | 8.75 | 15.25 |
| SJF | 7.75 | 14.25 |
| SRTF | 6.50 | 13.00 |
| Priority (preemptive) | 10.75 | 17.25 |
| RR, квант 3 | 13.50 | 20.00 |

`experiment.py` автоматически проверяет все пять эталонов и создаёт `comparison.csv`, `rr_quanta.csv`, график `rr_quanta.png` (если установлен matplotlib). В RR процесс, пришедший на границе кванта, включается в очередь **раньше** вытесненного. В SRTF и Priority при равенстве критериев текущий процесс не вытесняется.

## Aging / starvation

Встроенный тест создаёт `P0` с низким приоритетом и 40 коротких высокоприоритетных процессов. Без aging `P0` долго не запускается; с aging ожидающие получают каждые 2 такта улучшение эффективного приоритета. Первый старт `P0` происходит раньше. Aging уменьшает голодание, но может увеличить число переключений.

## Вывод

Малый квант RR уменьшает задержку первого ответа, но увеличивает переключения; большой делает RR похожим на FCFS. На set3 много коротких задач и одна очень длинная: SRTF обычно уменьшает среднее ожидание, но требует знания/прогноза остаточного времени задачи.
